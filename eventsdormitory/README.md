# EventsDormitory

Уютный дневник общежития №2 ГУАП: ул. Передовиков, д. 13. Организаторы — **Инициативные люди**, контакт — [@Ryctam9](https://t.me/Ryctam9).

Самостоятельное приложение на Go и стандартной библиотеке, без Node.js и внешних Go-зависимостей. Существующий React/Node-проект в корне репозитория сохранён; команды для нового сайта выполняются **из папки `eventsdormitory`**.

## Что работает

- Мероприятия с календарной полосой: выбор дня/диапазона, навигация по месяцам стрелками, отметки дней с событиями, выпадающий список категорий. Публичный список показывает только предстоящие события; кнопок месяцев и публичного архива нет.
- Пять событий октября 2026: настолки 10-го, ML-хакатон 18-го, кино 23-го, турнир 25-го, подготовка к Хеллоуину 31-го. Вайбкодинг 8 ноября. Настолки, кино и сентябрьский архив — явно обозначенные демонстрационные записи. Все времена и площадки пока предварительные.
- Три статьи дневника в виде сгенерированных разворотов переплетённого блокнота: знакомство с соседями, предложение встречи и первый хакатон. Текст и рисунки встроены в изображения. Каждый разворот открывается отдельно, поддерживает увеличение 100/200/300%, текстовую версию и дополнительные подробности. Дневник находится на странице `/blog`; блок с его статьями убран с главной. Шесть оригинальных обложек мероприятий и рисунок узнаваемого общежития по фотографии. Фанатская страница использует приложенное пользователем изображение: отдельная генерация для неё была отклонена генератором.
- Telegram OIDC (authorization code + PKCE, RS256/JWKS) и VK ID (code + PKCE, server-side user_info). Кнопки включаются после настройки провайдеров.
- «Приду» и отмена записи, личный кабинет с редактируемыми именем, фамилией, почтой, курсом, возрастом, факультетом и описанием. Поля не нужны для записи на мероприятия. Фото PNG/JPEG до 3 МБ сохраняется как квадратный JPEG 384×384; фотографии доступны только владельцу и администратору. Изменения профиля сохраняются после перезапуска и повторного входа через соцсеть.
- В личном кабинете отдельно показаны предстоящие записи и архив завершённых посещённых событий. Архив включает только подтверждённые организатором посещения. Старый `/archive` перенаправляет в `/profile#visited`. Личная коллекция достижений вынесена в `/achievements` и не дублируется в ЛК. Четыре достижения выдаются за посещения, ещё два — за действия на сайте.
- Админка `/admin`: публикация и редактирование событий/статей, черновики, список пользователей с поиском, регистрациями и посещениями, отметки присутствия.
- Скрытый фанатский уголок с Человеком-пауком. Вход появляется при наведении на небольшой участок в верхней части фонового рисунка слева (примерно четверть ширины страницы); доступен с клавиатуры. Прямой путь: `/roof/quiet-hour`.
- CSRF, HttpOnly/SameSite cookie, проверка Origin, ограничение запросов, лимит тела, экранирование пользовательских текстов, CSP. Сессии хранятся в памяти и прекращаются после перезапуска.

## Локальный запуск

Требуется Go 1.22+. Для публичного сервера используйте актуальный поддерживаемый Go.

PowerShell:

```powershell
cd eventsdormitory
$env:BASE_URL = 'http://localhost:8080'
$env:DEMO_MODE = 'true'
$env:ADMIN_TOKEN = 'ваш-случайный-длинный-ключ'
go run .
```

Открыть http://localhost:8080. Демопрофиль предназначен только для localhost и не имитирует вход в соцсеть. Админка: http://localhost:8080/admin, ключ — из `ADMIN_TOKEN`. `.env` читается Docker Compose; `go run` использует переменные окружения.

Linux/macOS:

```bash
cd eventsdormitory
BASE_URL=http://localhost:8080 DEMO_MODE=true ADMIN_TOKEN='your-long-random-key' go run .
```

## Подключить Telegram

1. Создать бота в [@BotFather](https://t.me/BotFather), открыть его **Login Widget** в mini app.
2. Добавить Allowed URLs: `https://peredovikov.ru` и **точный callback** `https://peredovikov.ru/auth/telegram/callback`.
3. Скопировать **Client ID и Client Secret** из этого раздела в `TG_CLIENT_ID` и `TG_CLIENT_SECRET`. Это OIDC-credentials; токен Bot API не заменяет Client Secret.
4. Оставить алгоритм подписи **RS256**: сервер проверяет подпись по JWKS, `iss`, `aud`, срок действия и `iat`. Другие алгоритмы здесь намеренно не включены.
5. Задать `BASE_URL=https://peredovikov.ru`, перезапустить приложение и пройти реальный вход.

Запрашиваем только `openid profile`: имя, идентификатор, доступный ник. Возраст, курс и почту Telegram не отдаёт. Телефон и доступ бота к сообщениям не запрашиваем.

[Официальная инструкция Telegram](https://core.telegram.org/bots/telegram-login).

## Подключить VK ID

1. Создать веб-приложение в кабинете [VK ID](https://id.vk.com/about/business/go).
2. Указать доверенный домен `peredovikov.ru` и Redirect URI **`https://peredovikov.ru/auth/vk/callback`**.
3. Записать ID приложения в `VK_CLIENT_ID`, включить разрешения на базовый профиль и `email`, если доступны приложению.
4. Установить `BASE_URL=https://peredovikov.ru`, перезапустить сайт и проверить полный вход.

Сервер использует `id.vk.ru/authorize`, `oauth2/auth` и `oauth2/user_info`, обменивает код с PKCE, `device_id`, проверяет `state` и получает профиль по access token. Токены VK не сохраняются. Провайдер может не вернуть email; возраст и курс не выводим как достоверно известные. Telegram и VK создают отдельные аккаунты; объединение аккаунтов не реализовано.

[Официальный VK ID SDK: реализация auth](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts).

**Без зарегистрированных приложений, credentials и разрешённых callback URL реальный вход не включится.** Сквозная проверка с реальными соцсетями выполняется после их настройки владельцем.

## Сервер и peredovikov.ru

```bash
cd eventsdormitory
cp .env.example .env
# заполнить ADMIN_TOKEN (случайный ключ минимум 32 символа), TG_*, VK_*
docker compose up -d --build
```

Контейнер слушает `8080`, опубликованный только на localhost хоста. Установить Caddy на сервере и использовать **`eventsdormitory/Caddyfile`**. Корневой `deploy/Caddyfile` относится к старому проекту на порту 3000. Направить DNS A/AAAA домена на сервер, открыть порты 80/443; Caddy получает сертификат и проксирует запросы на `127.0.0.1:8080`.

Один процесс приложения хранит данные в JSON-снимке `data/dormitory.json`; записи сериализованы mutex, снимок записывается через временный файл и атомарную замену. Для небольшого общежития это простая долговечная база. Несколько реплик с одним файлом не поддерживаются. При росте перенести хранение в SQLite/PostgreSQL.

Docker volume `events-data` содержит профили, записи, посещения, контент и папку `photos` с аватарами. Регулярно делать резервную копию всего volume. Начальная афиша создаётся только при отсутствии базы; дальнейшее редактирование — через админку. Изменения `seed.go` не перезаписывают уже сохранённые данные.

До публичного запуска: выключить DEMO_MODE, подтвердить времена и места мероприятий, утвердить правила обработки и сроки хранения данных. В админке нет кнопки удаления аккаунта; запросы на удаление принимаются через организатора, который удаляет профиль и связанные записи из резервно сохранённой базы при остановленном сервере.

## Проверки

```bash
go test ./...
go test -race ./...   # Linux / окружение с доступным C-компилятором
go vet ./...
go build ./...
node --test calendar.test.mjs  # Node.js нужен только для тестов календаря
```

Go-тесты проверяют запись/повторную запись/отмену, сохранение после перезапуска, отметку посещения, отказ записи на архив/черновик, роли, CSRF, скрытие черновиков, откат при ошибке записи, поддельный Telegram JWT и неизвестный OAuth state. Дополнительно проверяются сохранение и валидация полей профиля, сохранность ручных изменений после входа через соцсеть, приватность архива, загрузка/нормализация аватара и отказ доступа к чужой фотографии. Пять тестов календаря проверяют дни по Москве, границы месяцев/лет, високосные даты, одиночный день, прямой/обратный диапазон и фильтрацию. GitHub Actions проверяет новое приложение отдельно от существующего проекта.

## Оформление

Палитра: чернильный `#233545`, бумага `#f3eee5`, коралл `#b8533a`, приглушённый бирюзовый `#607c7c`, тёплый фон `#eae2d4`; основной цвет кнопок — `#b7513a`. Заголовки — Onest, основной текст — Golos Text; шрифты локальные с лицензиями OFL. Логотип — SVG с переменной толщиной контура дома и буквами Gochi Hand, переведёнными в векторные пути. Для его отображения не нужен шрифт или растр. Исходный шрифт и лицензия — `design/fonts`, инструмент сборки — `tools/build_marker_logo.py` (fontTools нужен только при пересборке логотипа).

Общежитие используется как фон верхнего блока слева, перед подвалом расположен сгенерированный студенческий уголок. Главная разделена на зоны фоном и отступами. Иллюстрации для сайта оптимизированы в WebP в `web/assets`; оригинальные PNG разворотов — в `design/diary-spreads`. Старые референсы вырванных листов сохранены в `design/references`, но больше не используются в текущем дневнике. Рисунки карточек достижений — собственные SVG. Правила размещения и источники собраны в [DESIGN.md](DESIGN.md).

Развороты содержат текст в пикселях и являются авторскими снимками содержания. Если меняется текст внутри иллюстрации, нужно обновить изображение и соответствующую текстовую версию в `web/journal.js`; редактор статьи в админке изменяет HTML-подробности, а не надписи в изображении. Новые статьи без заранее созданного разворота выводятся как обычная запись в оформлении блокнота.

Референсы: [Donatov](https://fun.donatov.net/events/), [ITMO Events](https://itmo.events/), [Орбита ГУАП](https://orbita.guap.ru/events/). От ИТМО — ясное разделение будущих и прошлых событий, от Орбиты — категории и видимые время/место. Donatov не загрузился в доступном браузере, поэтому его визуальный дизайн не использовался как проверенный образец. Прикреплённые изображения служили визуальными референсами; изображения мероприятий созданы отдельно.

Факты фанатской страницы: [Amazing Fantasy №15](https://www.marvel.com/comics/issue/16926), [Ultimate Fallout №4](https://www.marvel.com/comics/issue/39962/ultimate). Персонажи принадлежат Marvel.
