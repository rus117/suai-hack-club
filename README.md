# SUAI Hack Club

Сайт двух хакатонов в общежитии №2 ГУАП: **Campus ML — 18 октября 2026**, **Вайбкодинг — 1 ноября 2026**. Домен: **peredovikov.ru**. Регистрация, подготовка, полноценное ML-задание с автоматическим рейтингом и закрытый кабинет организатора.

## Что работает

- Отдельная регистрация на каждое событие; заявки сохраняются в SQLite на сервере.
- Сервер закрывает регистрацию Campus ML и приём заданий 16 октября в 00:00 МСК; регистрацию на вайбкодинг — 28 октября в 00:00 МСК.
- Задание «Час пик»: синтетические данные, 1 200 обучающих и 300 тестовых строк; стартовый Python-скрипт; загрузка CSV и ссылки на решение.
- Автоматический F1, максимум 5 успешных отправок в московские сутки. До дедлайна рейтинг по 200 открытым строкам, после — по 100 закрытым. Для финального рейтинга выбирается лучшая открытая отправка каждого участника.
- `/admin`: вход по паролю, поиск, фильтры, статусы, выгрузка CSV, ссылка на решение, восстановление кода, удаление заявки вместе с результатами.
- Материалы для новичков по ML, валидации, вайбкодингу, Git, работе в команде и защите.
- Адаптивный интерфейс, локальные шрифты, клавиатурная навигация. Без рекламных счётчиков.

## Запуск на сервере — Docker

Нужны Git, Docker с Compose и обратный прокси для HTTPS. Никаких платных API или внешней базы данных не требуется.

```sh
git clone https://github.com/rus117/suai-hack-club.git
cd suai-hack-club
# Однократно: создаёт .env и отдельный файл .admin-password.
docker run --rm -v "$PWD":/app -w /app node:24-bookworm-slim node server/setup.mjs
docker compose up -d --build
```

В `.env` уже указан `PUBLIC_ORIGIN=https://peredovikov.ru`. При использовании другого адреса замените значение на точный HTTPS origin без завершающего `/`. Не запускайте setup повторно и не заменяйте `DATASET_SECRET` после выдачи данных участникам.

Приложение слушает **127.0.0.1:3000**. Направьте A/AAAA домена на сервер. Для Caddy, установленного непосредственно на сервере, используйте [deploy/Caddyfile](deploy/Caddyfile): он получает и обновляет HTTPS-сертификат. Порты 80 и 443 должны быть доступны. Если уже используется Nginx, направьте прокси на `http://127.0.0.1:3000`, передавайте `Host`, `X-Forwarded-Proto` и перезаписывайте `X-Forwarded-For` действительным адресом посетителя. Не выставляйте порт приложения напрямую наружу.

Админка после подключения домена: **https://peredovikov.ru/admin**. Пароль находится в `.admin-password` на сервере. Сохраните его в менеджере паролей и удалите этот файл. `.env`, пароль, данные и резервные копии не попадают в GitHub. **Не публикуйте их и не кладите в каталог статических файлов.**

Проверка после запуска: открыть сайт, отправить собственную тестовую заявку, войти в админку, проверить заявку и удалить её. Статус контейнера: `docker compose ps`; журнал: `docker compose logs --tail=100 web`.

### Обновление и резервные копии

```sh
git pull --ff-only
docker compose up -d --build
```

Заявки и закрытые ответы живут в именованном томе `club-data`. **Не используйте `docker compose down -v`: эта команда удаляет данные.**

Перед обновлением сделайте согласованную копию SQLite и набора данных:

```sh
docker compose exec web node server/backup.mjs /app/data/backup-current
mkdir -p backups
docker compose cp web:/app/data/backup-current ./backups/
chmod -R go-rwx backups
```

Копии храните приватно, желательно на другом носителе; отдельно сохраните `.env`. Для восстановления остановите приложение, верните `club.sqlite` и `dataset.json` из одной копии в каталог данных, удалите оставшиеся `club.sqlite-wal` и `club.sqlite-shm` от остановленной базы, восстановите владельца `node` (UID 1000), запустите контейнер. Делайте это только после резервного копирования текущего состояния. История отправок зависит от неизменного `dataset.json`.

## Локальный запуск без Docker

Node.js **24+** (используется встроенный `node:sqlite`).

```sh
npm ci
npm run setup
npm run build
npm start
```

Открыть http://127.0.0.1:3000. Для разработки: `npm run dev:server` и `npm run dev` в двух терминалах. Для работы без Docker на сервере установите `NODE_ENV=production`, используйте HTTPS-прокси и менеджер процессов с автоматическим перезапуском.

## Проверки

```sh
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

Тесты используют отдельную базу в памяти и фиксированную дату до дедлайнов. Проверяют регистрацию, доступ к админке, CSRF, дедлайны, CSV, рейтинг, лимиты, восстановление кода, удаление, пользовательский путь, доступность и ширину страниц. Тестовые пароли работают только в тестовом процессе.

## Что настроить организатору

Даты и основные тексты событий: `shared/events.json`. Год установлен **2026**. Время начала, номер комнаты, имена жюри и призы не выдуманы — их нужно объявить в канале. Подготовка программы и жюри описана в [docs/ORGANIZER.md](docs/ORGANIZER.md). Регистрация не отправляет Telegram-сообщения автоматически: организатор связывается с участниками сам по данным из кабинета.

Технологии: React, TypeScript, Vite, Express, SQLite. Приложение рассчитано на небольшой клуб и **один экземпляр сервера** с постоянным диском. Источники идей и навыки дизайна: [docs/SOURCES.md](docs/SOURCES.md).
